The Daily Assistant

The Assistant lives inside the app: its agent loop runs in Electron's main process, and its model is a remote OpenAI-compatible API or a local llama-server. Its tools call StorageController directly, with no server and no OAuth; from there a change spreads exactly like a manual edit. For agents, see the other diagram.

The key idea: the model only proposes calls, and AIController runs them. Every call goes through a schema check and policyHook; a destructive one waits for Confirm in the window. The person sees only what the model hands to the respond tool, which ends the turn. Writes land in the local SQLite, and sync and the other windows hear about them from the same notifyLocalChange a manual edit fires.

How the model's tier is chosen

tierwhenprompt · toolstool_choice
tinylocal "fast"; remote *nano* or ≤4Btiny · compactauto
mediumlocal "balanced"; *mini*/*small* or ≤14Bcompact · compactrequired
largelocal "quality"; any other remotefull · fullrequired
  • Reasoning models (o-series, deepseek-r/v4+, qwq, *thinking*) reject required, so they get auto.
  • Compat mode is for a local model without native tool calls: the schemas go into the system prompt as text, and calls are parsed from the reply.
  • Under auto the model may answer in plain text, and that is a final answer too.
