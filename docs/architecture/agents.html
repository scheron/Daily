Agents and data in Daily

An agent — Claude Code, the Claude app on a phone, Codex — never talks to a Mac. It reaches the Daily Sync Server over MCP, gets access through OAuth, and a person approves it on one of their Macs. The server holds all the work as one opaque snapshot and opens it only for the length of a tool call.

The key idea: the server keeps no task tables. For each tool call it starts packages/core on an in-memory SQLite, loads the snapshot into it, runs the tool through the same services the app runs, and writes the snapshot back with a conditional write at the revision it read. Macs learn about it from the /v1/revision long-poll and pull the change with an ordinary sync (LWW).

A fixed set: AGENT_TOOLS = READ_TOOLS + WRITE_TOOLS. Attachments are read from assets/ on the server.

Rules

  • Agents exist only on a server with HTTPS and a trusted certificate, or on loopback. Self-signed, iCloud and no sync get none.
  • An agent never moves Snapshot.version: newer than the server — refused; older — read only until the Macs update.
  • A write is attributed to the agent's Mac (written_by_device_id), and "today" follows that Mac's time zone.
  • Revoking a device revokes its agents. A Child revokes its own, the Parent any.
  • The server resolves no conflict: a conditional write, and a lost race is reread and reapplied.

Not to be confused with

The in-app Assistant takes another path: its agent loop runs in the main process (apps/desktop/src/main/ai/), and its tools call the local StorageController directly, with no server and no OAuth.

An agent sees the work only through the server, so it works while every Mac sleeps (ADR 0004). See the Assistant's diagram.
