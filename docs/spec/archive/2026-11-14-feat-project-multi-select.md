# Plan: Несколько проектов в меню дока через Cmd

## Result

Меню проектов в доке выбирает либо один проект, либо все сразу: посмотреть на два-три проекта вместе нельзя. После плана во фрейме Day `Cmd`+клик собирает набор из любых проектов, включая No project. Список задач сразу показывает задачи набора, кнопка в доке показывает, что выбрано. Набор ведёт себя как All projects в своих пределах и переживает перезапуск. Задача в Daily: `DT-qi4uUNiiI9GZOL9R0Omx8`, решения в её комментарии.

## Approach

Выбор в доке становится набором id проектов в локальных настройках Mac, рядом с нынешними `activeId` и `isAllProjects`. Хранилище проектов отвечает на три вопроса: какие проекты сейчас в фильтре, все ли это проекты, больше ли их одного. Последнее заменяет нынешнюю проверку режима All projects у всех потребителей, и набор получает поведение All projects без отдельного разбора каждого места. Меню в доке читает `Cmd`, остальные меню проектов его не видят.

- All projects остаётся флагом, а не списком всех id. Набор, в котором отмечены все проекты, превращается во флаг: так проект, созданный позже, сразу виден в All projects.
- Набор хранится в порядке добавления, `activeId` — последний проект набора. Фрейм Milestone и всё, чему нужен один проект, читают `activeId` как сейчас и не меняются.
- Старые настройки читаются как набор из одного `activeId`: обновление не сбрасывает выбор.
- Версию снапшота не поднимаем: настройки не синхронизируются, `normalizeSnapshotDocs` их отбрасывает.
- `Cmd`+клик по X при All projects даёт набор из всех проектов, кроме X, в порядке меню. `activeId` остаётся прежним, если это не X; если X, им становится последний проект набора.
- Проект, удалённый в Settings, выпадает из набора. Если набор опустел, выбор падает на No project, как сейчас при удалении активного проекта.

## Out of scope

- Мультиселект в деталях задачи, в контекстном меню карточки и во фрейме Milestone.
- `Cmd+Enter` в поиске меню и переключение строк с клавиатуры.
- Синхронизация выбора между Mac.
- Переименование `Branch` в project.
- Другой проект для новой задачи: она уходит в No project, даже если его нет в наборе.

## Done and Spec

```text
## Done

1. Во фрейме Day выбран проект A; навести на меню в доке, `Cmd`+клик по B → меню открыто, галочки у A и B, видны задачи обоих проектов с подписью проекта на карточках, на кнопке «A, B» с иконкой слоёв.
2. `Cmd`+клик по C → на кнопке «A, B +1».
3. `Cmd`+клик по B → галочка с B снята, его задач нет; когда отмечен только A, `Cmd`+клик по A → ничего не меняется.
4. Клик без `Cmd` по B → выбран только B, меню закрыто.
5. `Cmd`+кликами отметить по одному все проекты → галочка появляется и у All projects, на кнопке «All projects»; `Cmd`+клик по A → отмечены все, кроме A, у All projects галочки нет.
6. `Cmd`+клик по All projects → выбрано всё, меню закрыто, отмечены All projects и каждый проект.
7. Отметить No project и A → видны только задачи без проекта и задачи A.
8. Выбраны A и B, B добавлен последним; перейти во фрейм Milestone → в меню отмечен только B, видны milestone проекта B; вернуться в Day → снова A и B.
9. Выбраны A и B, в обоих есть тег «bug»; выбрать «bug» в доке тегов → задачи с «bug» из обоих проектов.
10. Выбраны A и B; создать задачу шорткатом и через Quick Task → обе задачи в No project.
11. Выбраны A и B; открыть из поиска задачу проекта C → выбран один C; снова собрать A и B, открыть из поиска задачу A → выбор не меняется.
12. Выбраны A и B; удалить B в Settings → выбран один A.
13. Выбраны A и B; перезапустить приложение → выбраны A и B.
14. В деталях задачи и в контекстном меню карточки `Cmd`+клик по проекту → выбран один проект, меню закрыто, как раньше.
15. Открыть меню в доке при наборе → серые галочки справа у каждого выбранного проекта, подпись на кнопке читается в доке — you check
```
